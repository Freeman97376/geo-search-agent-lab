# 本地复现与真实平台的差距：指标及判定协议

日期：2026-09-28。状态：可供实施的设计草案；尚未采集平台样本、实现评分器或产生实测结果。用户已选定 **ChatGPT、Claude、Gemini 的网页端**为第一轮参照；具体网页模式、账号设置和正式容忍阈值待确定。本协议补充 [Query 评估协议](query_evaluation_protocol.md)，不改变上游行为。

## 1. 比较对象与观测范围

每个平台、网页/API 接口分别对照，保持用户原问题、语言、地区、时间窗口、会话条件尽量一致，记录不可控制项。问题集按主题家族划分开发集和保留验证集；同题改写不得跨集合。

平台内部 Query、检索结果和上下文只有确实返回时才比较。分别标为 complete / partial / unobserved；缺失不填零，不从最终引用反推唯一内部路径。外部平台不能冻结的搜索索引和缓存是观测限制，不假装已经控制。

| 层 | 可比数据 | 指标候选 |
| --- | --- | --- |
| Query 规划 | 实际可见的搜索 Query；由独立需求标注进行映射 | 需求覆盖频率误差、约束遗漏频率误差 |
| 召回 | 明确可见且定义可比的候选来源 | URL/域名重叠、关键证据覆盖差异 |
| 最终引用 | 正文引用及目标链接，保留与文末参考文献的区别 | 目标域名引用概率误差、来源分布距离 |
| 回答质量 | 原问题、回答及引用的页面快照 | 答案需求覆盖、事实支持率的差异；独立于行为相似性 |
| 策略效果 | 两边可比的优化干预及对照结果 | 效果幅度误差、方向一致性、策略选择损失 |

能测到的末端行为接近，不证明内部机制相同；中间环节不可观测时，只能声明末端对齐程度。

## 2. 第一项主指标：按题比较引用概率

预先选定目标页面/域名 d。对问题 q，令 Y=1 表示一次有效搜索回答在正文中至少引用该目标一次，否则为 0。重复引用同一目标不累计成多次成功。技术失败或字段不可观测单列，不能当成成功回答中的未引用。

分别估计本地与平台的 p_local(q,d)、p_platform(q,d)。给出每题差值及其区间，然后按预定问题权重汇总：

`MAE(d) = Σ_q w(q) × |p_local(q,d) − p_platform(q,d)|`，其中 `Σ_q w(q)=1`。

初版可以题目等权，标为 benchmark 分布；有可信业务需求权重后另报业务加权值。不得用自己生成 Query 的次数充当真实需求权重。另报带符号的平均偏差，区分整体高估/低估；不能只报带符号均值，让相反误差互相抵消。

比例差用“百分点”。有限重复得到的概率含有抽样误差，因此经验 MAE 也含估计噪声，不能直接解释为精确的真实模型误差。对多个目标分别呈现，预先声明主指标与多重比较规则，避免看过结果后挑最相似的域名。

还应独立报告所有尝试中产生目标引用的成功比例、技术失败率和无搜索率，避免通过排除失败来美化指标。

## 3. 第二项指标：比较来源分布

不同域名可以在同一回答共现，域名“出现概率”之和不一定为 1。不能直接把这些边际概率送进会自动归一化的分布距离函数，随后仍称它们为出现概率。

若比较来源份额，明确采用以下一种定义并锁定版本：

1. 每条有效回答先按域名去重；有 m 个域名时，每个分配 1/m 权重，使每条回答权重相同。
2. 有效回答没有引用时，为独立类别 `no_citation` 分配权重 1；技术错误另报。
3. 对同题的重复回答取平均，得到和为 1 的来源份额分布。
4. 本地与平台使用同一域名支持集合，未出现项补零。域名规范化规则固定；若合并长尾为 other，分桶规则必须预先固定并披露。

可用 **Jensen–Shannon 距离**比较两组份额。选定以 2 为底时范围为 0–1；0 表示当前定义下分布相同，1 为最大差异。SciPy 的 `jensenshannon` 返回的是 JS 散度的平方根，即距离，不能混用名称或阈值。[SciPy 官方定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.distance.jensenshannon.html)

同时报告每条回答的引用域名数、每个目标域名的出现概率。来源份额相同，仍可能有总引用量或共同出现模式的差异；JS 距离不是充分的整体相似性指标，也不应写成 `1−距离=平台复现准确率`。

URL/域名集合的 Jaccard 重叠可作辅助解释：交集大小除以并集大小。两边都为空时记 N/A 并计入无引用统计，不奖励为高相似；仅一边空且另一边非空时为 0。跨重复运行的所有组合不是独立新样本。

## 4. 先测平台自身的波动

对同一问题多次采样，分别观察：平台对平台、本地对本地、本地对平台的差异。估计分布距离的自对照时，平台重复运行可拆成两个等样本量组，跨系统比较也保持相同样本量，避免纯粹因样本多少产生不公平差距。

这提供噪声参照，但平台自身波动不是自动成立的“相似度上限”。不能机械地把两个距离相减并称为已剔除噪声的真实差距，也不能仅因跨系统距离落入自对照范围就宣布等价。少量重复仅用于先导检查；正式样本量要对应目标精度。

按题聚合后做配对比较，保留同主题、同题重复和时间块的相关结构。可考虑主题组层面的配对重采样或适合该设计的分层模型；不能把每条引用、所有运行组合当成独立样本扩大 n。方法选择与样本量需要匹配。[重复采样、聚类与配对比较参考](https://www.anthropic.com/research/statistical-approach-to-model-evals)

## 5. 判定“足够接近”

先确定某项指标允许的偏差范围，再评估；阈值要与使用场景相关，不能事后调整到恰好通过。给出差值及置信区间，避免只报告 p 值。

对于带符号的引用率差，可采用适配配对/聚类数据的等价性评估；两独立二项样本的现成 TOST 函数不能直接用于混有同题重复的整体数据。对于 MAE 或分布距离等非负指标，应评估其上界能否低于预定阈值，不能盲套比例差检验。[独立比例 TOST 的假设与定义](https://www.statsmodels.org/dev/generated/statsmodels.stats.proportion.tost_proportions_2indep.html)

默认报告 95% 置信区间。若采用显著性水平 0.05 的标准 TOST，则使用与该检验相匹配的两次单侧检验/90% 双侧区间，并明确标注；不要把不同区间与检验结果混在一起。

纯示意：本地目标引用率 55%，平台 50%，点估计相差 +5 个百分点；假设事先容忍范围为 ±10 个百分点，而适用区间是 −2 至 +12。区间越过容忍上界，尚不能判定足够接近；也不能由此直接判定不等价。该例不是项目实测或正式阈值。

一个总体均值通过不足以覆盖所有场景。按平台、接口、主题、语言和时效性报告重要分层，保留失败/不确定切片；多指标结论须按事先声明的联合判定或多重比较方案解释。

## 6. 商业应用更关键：策略判断是否一致

在本地和平台分别估计同一项可比优化 a 相对未优化对照的效果：

`Δ_local(a) = outcome_local(优化) − outcome_local(对照)`

`Δ_platform(a) = outcome_platform(优化) − outcome_platform(对照)`

比较 `Δ_local(a) − Δ_platform(a)` 的幅度和区间。还可以报告优化策略排序的一致性；近零或区间过宽的效果标为方向不确定，不强行算成正/负。相关性高也可能存在系统性的幅度高估，必须与幅度误差并列。

如果只有引用数据，这里的 outcome 只能称为引用效果；不能写成盈利效果。有可信增量利润数据后，再评估本地选择策略在真实环境中的机会损失：

`选择损失 = 已测试候选中真实预期净收益最高者的收益 − 本地所选策略的真实预期净收益`。

“最高者”只限已测试候选，未知的全局最优不可声称；直接从噪声数据挑最大值会有选择偏差，应使用独立验证样本，并传播估计不确定性。成本、观察周期和目标客群必须可比。

本地内容快照实验与真实互联网的变更不自动构成相同干预。外部验证需确认平台可接触相应内容版本，记录索引/缓存/时间条件并设置合理对照；没有这一条件，只能进行结果分布对齐，不能验证优化效果迁移。未经用户授权不发布页面变更或进行付费平台调用。

## 7. 最小报告格式与下一步

每个平台单独输出：

| 内容 | 必须包含 |
| --- | --- |
| 样本说明 | 独立主题/问题数、每题重复、时间窗口、平台/接口与可观测程度 |
| 主要差距 | 目标引用概率 MAE、带符号偏差、区间、来源份额 JS 距离 |
| 噪声与可靠性 | 平台及本地自身波动、失败率、无搜索与无引用比例 |
| 分层结果 | 各主题/语言等重要切片，遗漏需求与异常来源 |
| 策略迁移 | 效果差、方向/排序一致性；未执行可比干预则标“未评估” |
| 使用结论 | 支持的用途和范围；通过、不确定、未通过，附容忍阈值及版本 |

下一步针对已选定的三个网页端建立标注和原始样本格式，再做少量重复采样估计波动。每次记录界面实际展示的模式/模型、搜索是否触发和可见引用；未知项保持 unknown。没有真实样本时，只能验证日志与计算方法，不能给出实际平台差距或“已复现百分比”。

## 8. 网页参照与 API 成本边界

网页端是用户已确定的参照对象。API 可作为另外一组可编程实验，不能直接替代网页产品，也不能因模型品牌相同就合并结果。网页采样还要考虑账号配额、人工核查时间及实际可见字段；当前未读取账号、提交研究问题或调用商业 API。

成本按 `题目数 × 每题重复次数 × 实验配置数` 估算，再叠加每次真实工具调用与计费 token。示意规模：30 题 × 3 次 × 3 家 = 270 次回答，即每家 90 次；增加页面变体、模式、日期轮次会进一步倍增。此规模用于探索，不保证足以做精确概率估计或等价性检验。

2026-09-28 查询的官方搜索工具单价（美元，不含模型 token）：

| API | 计费单位/单价 | 假设每家 90 次回答、每次恰好 2 次计费搜索 |
| --- | --- | --- |
| OpenAI 非 preview 的 Web Search | $10 / 1,000 次工具调用 | $1.80 |
| Claude Web Search | $10 / 1,000 次搜索 | $1.80 |
| Gemini 3.x Search Grounding | 超出适用免费额度后 $14 / 1,000 条搜索 Query | $2.52，不扣免费额度的示意计算 |

这三个数仅为工具费示例，合计 $6.12，不是总账单或费用上限。一次回答可能多次搜索；三家的计费单位并不完全相同。Gemini 官方定价列出 3.x 模型共享的每月 5,000 次免费搜索额度，实际剩余额度、资格与账户计费需另查；2.5 等旧模型的计费方式不同，不套用本表。

来源：[OpenAI 官方 API 定价](https://developers.openai.com/api/docs/pricing)、[Claude 搜索工具计费](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)、[Gemini API 定价](https://ai.google.dev/gemini-api/docs/pricing)、[Gemini 搜索计数规则](https://ai.google.dev/gemini-api/docs/google-search)。

完整费用算例仅为说明预算，不表示选定模型或声称匹配网页 Claude：Claude Sonnet 4.6 的标准输入/输出价分别为 $3/$15 每百万 tokens。若一次回答的**全部累计计费量**为 6,000 输入 tokens、1,500 输出 tokens（包含计费思考等输出），且搜索两次，则费用为 `6000/1e6×3 + 1500/1e6×15 + 2×0.01 = $0.0605`，90 次为 `$5.445`，约 $5.45。搜索结果、多轮累计和工具提示都须包含在输入预算里，不能只计算用户原问题字数。[Claude 官方定价](https://platform.claude.com/docs/en/about-claude/pricing)

上述 token 用量是假设，不是实测均值；长文本、思考、多轮阅读、重试、其他工具、评审模型及更贵模型都可能增加费用。这里不计税、特殊服务层和未发生的折扣，不能把搜索工具费或这个单模型算例当成三家完整预算。

如果后续启动 API 实验，先做少量有明确总预算的样本，根据 usage 返回值更新预估；运行器需有调用次数、累计预算和重试上限。调试主要使用快照；重复采样用于估计真实波动时必须另行标明，不能用复制缓存替代独立试验。限制输出/搜索会改变行为，应作为固定实验配置披露。当前只讨论费用，没有 API 调用预算授权，也未实现这些限额机制。
